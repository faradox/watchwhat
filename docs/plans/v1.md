# watchwhat v1: plan and decisions

**Status: M0-M2 written 2026-11-09 (backend and frontend tests pass, pages
checked at phone width). Next: M3, live on breathdance
([11](#11-deployment-on-breathdance)).**

watchwhat answers "what movie could we watch tonight?". A small shared list
of movies, each enriched from TMDB and tagged by an LLM, plus a recommender
that shows one matching movie at a time at random. Built for a household of
two, runs standalone, and on breathdance uses the shared Postgres and
Authelia.

## 1. Features

v1:

- **Add** (login): type a title, optionally the year; pick the right match
  from TMDB results with posters; an LLM drafts tags and a short blurb; edit,
  save.
- **Recommend** (public): optional filters, then one movie at a time in
  random order: poster, title, year, runtime, blurb, tags, trailer button,
  IMDb link. "Next" moves on; no repeats until the matches run out.
- **Seen** (login only), per person: one chip per person plus "Both" for
  movies watched together. Logged in, the recommender's seen filter offers
  "neither of us has seen it" (default), "<name> hasn't seen it" and "include
  seen movies". Logged out, seen status does not exist: the API never returns
  it and the filter is not shown.
- **Library** (public): all movies, searchable and filterable; edit, delete,
  "never suggest" and seen toggles when logged in.
- **Priority** (login): "we both really want this" weights a movie up in the
  random order.

Not in v1 (backlog, [8](#8-milestones)): natural-language filter input, bulk
paste import, post-watch thumbs, "find more like the ones we loved",
two-phone swipe mode, streaming availability (declined).

Out of scope: notes, multiple households, user accounts beyond the proxy or
basic login.

## 2. Data source: TMDB

IMDb forbids scraping and its API is paid, so facts come from the TMDB API
(free for non-commercial use with attribution). One request per movie:
`GET /3/movie/{id}?append_to_response=videos,keywords,external_ids,credits`.

| Field | From |
|---|---|
| `title` (English), `original_title`, `original_language` | details |
| `year`, `runtime_min`, `genres`, `overview`, `poster_path`, `vote_average` | details |
| `imdb_id` (IMDb link) | `external_ids` |
| `trailer_youtube_key` | `videos`: official YouTube trailer, else any YouTube trailer, else teaser |
| `keywords`, director, top cast | `keywords`, `credits` (LLM input and display) |

- Display: the original title as the main title. When it is in a non-Latin
  script (e.g. 七人の侍) or differs from the English one, the English title is
  shown underneath, so it stays readable.
- Trailer fallback: no YouTube key means a YouTube search link
  (`<title> <year> trailer`). No IMDb id means no IMDb link.
- Posters are loaded from `image.tmdb.org` (no local copy in v1).
- Attribution in the footer: TMDB logo plus "This product uses the TMDB API
  but is not endorsed or certified by TMDB."
- Credentials: the TMDB API Read Access Token (`TMDB_TOKEN`). Without it,
  movies can still be added by hand.
- Manual entry for films TMDB does not know: title, year, runtime and
  description entered by hand, the LLM tags from that alone, the movie is
  marked "not verified".

## 3. Tags

Fixed vocabularies, defined in one backend module and served to the frontend
via `GET /api/vocab`, so a new value means one code change and no migration.

| Group | Values | Cardinality | Set by |
|---|---|---|---|
| Genre | TMDB genres (Action, Comedy, Horror, Thriller, ...) | many | TMDB |
| Mood | feel-good, funny, cozy, romantic, tense, dark, mind-bending, tearjerker, epic, weird | 1-3 | LLM, editable |
| Attention | brain-off, normal, full-focus | 1 | LLM, editable |
| Violence/gore | 0 none, 1 mild, 2 strong, 3 graphic | 1 | LLM, editable |
| Scariness | 0-3 | 1 | LLM, editable |
| Heaviness | 0 light, 1 some weight, 2 heavy, 3 devastating | 1 | LLM, editable |
| Decade | from `year` | derived | - |
| Runtime | from `runtime_min` | derived | - |
| Language | `original_language` | derived | - |

## 4. Adding a movie

```text
title [+ year] -> GET  /api/private/tmdb/search   -> candidates (poster, year, overview)
pick one       -> POST /api/private/drafts        -> TMDB details + LLM tags -> draft
edit, save     -> POST /api/private/movies        -> stored
```

- Duplicate check by `tmdb_id` before the LLM call ("already on the list").
- The draft is not stored; closing the page discards it.
- **LLM call**: `claude-haiku-5-5`, Anthropic Python SDK, one request with
  structured output (`output_config.format`, JSON schema with the
  enums from [3](#3-tags)), low effort. Input: the TMDB facts (title, year,
  genres, keywords, overview, director, cast). Output: moods, attention,
  three intensity levels, a spoiler-free blurb of at most 40 words. About
  2k tokens per movie, well under a cent.
- The LLM never supplies facts (year, runtime, plot); those come from TMDB.
- Without `ANTHROPIC_API_KEY` the draft has empty tags and the TMDB overview
  as the blurb; tags are set by hand.

## 5. Recommender

- Filters, all optional, combined with AND; values within one group with OR:
  genres, moods, attention, max violence / scariness / heaviness, decades,
  language (any / English / not English), time budget.
- **Time budget** has two forms: "at most N minutes", or "we have until
  HH:MM" (the browser computes the minutes from now, minus 10 minutes slack).
- Logged in: "hide movies we've seen" (default on).
- Filtering and the random order run in the browser
  (`frontend/src/lib/filters.js`): the page loads the whole list once (public
  or private, by login) and every filter change is instant. Fine up to
  thousands of movies. The order is a seeded weighted shuffle (priority
  movies weigh 3x; Efraimidis-Spirakis), so it stays put while you flip
  through. At the end: "That was all N. Shuffle again?"
- A movie that is marked as seen stays on screen until "Something else".
- The match count updates live as filters change ("23 of 140 movies match").
- Values within a group are OR'ed, groups AND'ed. A movie without a value is
  left out by list filters (genre, mood, attention, decade, language) but kept
  by "at most" filters (intensity, time).
- Filters live in the URL query, so a filtered view can be shared or
  bookmarked.
- "Never suggest" movies are excluded everywhere except the library.

## 6. Auth: public vs. logged in

Two API prefixes:

- `/api/...`: public, read-only. Never returns seen status, priority edits or
  who added what. nginx clears `Remote-User` here.
- `/api/private/...`: every write, the TMDB search, drafts, seen, and the
  full list with seen status.

The frontend calls `GET /api/private/me` on load: 200 means logged-in mode,
401 or 403 means public mode, with a "Log in" link to `/api/private/login`
(redirects home after the login). With `basic`, only that link sends the
Basic challenge, so visitors never see a browser login dialog. Writes also
need a same-origin `Origin` (or no cross-site `Sec-Fetch-Site`).

`AUTH_MODE` (same pattern as nawfit and murmur):

| Mode | Use | How |
|---|---|---|
| `proxy` | breathdance | `Remote-User` from nginx + Authelia, trusted only with the matching `X-Proxy-Secret`; name must be in `ALLOWED_USERS` |
| `basic` | standalone | HTTP Basic on `/api/private/`, checked by the backend against `BASIC_PASSWORD` |
| `none` | local dev | everyone is the first name in `ALLOWED_USERS` |

Production refuses to start with `proxy` and no secret or users, or `basic`
and no password or users.

## 7. Architecture

Same stack and layout as nawfit:

```text
watchwhat/
  backend/   FastAPI, async SQLAlchemy, Alembic, httpx (TMDB), anthropic SDK
  frontend/  React + Vite + Tailwind, built into nginx (prod) / Vite dev server
  docker-compose.yml   profiles dev / prod; SQLite by default, Postgres on breathdance
  Makefile             setup-dev, run-dev, stop, build, run, logs, shell, test
```

Tables:

```text
movie        id, tmdb_id (unique, null for manual), imdb_id, title,
             original_title, original_language, year, runtime_min,
             genres[], keywords[], overview, blurb, poster_path,
             trailer_youtube_key, vote_average, director, cast[],
             moods[], attention, violence, scariness, heaviness,
             priority (bool), never_suggest (bool), verified (bool),
             added_by, created_at, updated_at
seen         movie_id, user_name, seen_at          (PK movie_id + user_name)
```

Lists are JSON columns (work on SQLite and Postgres alike); filtering happens
in Python after a coarse SQL filter. Fine for a list of hundreds, revisit at
tens of thousands.

Frontend: mobile-first (it is used on the couch), dark by default, three
routes: `/` recommender, `/library`, `/add`.

The web app's nginx also proxies `/api` to the backend, so a standalone
install needs one port. SQLite is allowed in production (one household's
list fits in a file).

Tests: pytest for the backend with TMDB and Anthropic faked
(`tests/fakes.py`); vitest for filter, time-budget, URL and shuffle logic. A
tagging check against the real API exists only as an opt-in script that Felix
starts (`make try-tagging`); it is never part of `make test`.

Public repo: MIT license, no breathdance domains or secrets in code; all
settings via env (`DATABASE_URL`, `AUTH_MODE`, `PROXY_SECRET`,
`ALLOWED_USERS`, `BASIC_PASSWORD`, `TMDB_TOKEN`, `ANTHROPIC_API_KEY`,
`LLM_MODEL`).

## 10. Decision log

2026-11-09:

- Subdomain `watchwhat.breathdance.net`.
- Facts from TMDB, not IMDb; IMDb link via the id, trailer via YouTube.
- Movies and documentaries only; series later, if ever.
- Public list and recommender; seen status and its filter only when logged
  in. No notes.
- Interface in English; titles in the original language (you watch original
  with subtitles).
- No streaming-availability filter.
- The list is filled together once the site is live; no import format
  needed for v1.
- New Anthropic API key for this app; `claude-haiku-5-5` for tagging, drafts
  reviewed before saving.
- Fixed tag groups as in [3](#3-tags).
- Stack as nawfit: FastAPI + React/Vite/Tailwind.
- Authelia group `family` for both users.
- Seen per person, with a "Both" chip for movies watched together.
- Filtering and shuffling in the browser instead of a server endpoint
  (instant filters, simpler API).
- SQLite allowed in production for standalone installs; breathdance uses
  Postgres.
- The login link is `/api/private/login` (no separate `/login` page).

## 11. Deployment on breathdance

Done by Felix; Claude writes the config and hands over the commands.

- Ports: frontend `127.0.0.1:8103`, backend `127.0.0.1:8104`. Subnet
  `172.29.13.0/24`.
- Postgres: database `watchwhat` (add to `configs/postgres/init-databases.sh`
  for fresh installs; on the running server `createdb` by hand, since the init
  script only runs on first start).
- Env (root `.env`): `WATCHWHAT_DATABASE_URL`, `WATCHWHAT_PROXY_SECRET`,
  `WATCHWHAT_ALLOWED_USERS`, `WATCHWHAT_TMDB_TOKEN`,
  `WATCHWHAT_ANTHROPIC_API_KEY`.
- nginx: `= /api/private/login` with `authelia-authrequest.conf` (redirect
  to the portal); `/api/private/` with `authelia-authrequest-api.conf` (401);
  both with the proxy secret include
  (`/etc/nginx/secrets/watchwhat-proxy-secret.conf`); `/api/` public with
  `Remote-User` cleared; `/` the frontend.
- Authelia: group `family` added to both users in the users file (Felix keeps
  `admins`), rule `domain: watchwhat.breathdance.net`, subjects
  `group:admins` and `group:family`, `two_factor`. nginx only asks for the
  private paths, so no bypass rule is needed.
- DNS record and certificate expansion for the subdomain.
- Root repo: `.ghettogitignore` entry, deploy target, `CLAUDE.md` and
  `docs/identity.md` tables, `docs/new_website_setup.md` subnet list.
